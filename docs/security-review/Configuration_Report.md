## Environment Files

| File | Tracked in Git | Contents | Risk |
|------|---------------|----------|------|
| `.env` | ❌ (gitignored) | `VITE_API_BASE_URL=http://localhost:8080` | Low (dev only) |
| `.env.development` | ❌ (gitignored) | `VITE_API_BASE_URL=http://localhost:8080` | Low |
| `.env.example` | ✅ (tracked) | `VITE_API_BASE_URL=http://localhost:8080` | Informational |
| `.env.production` | ✅ (tracked — NOT in gitignore) | `VITE_API_BASE_URL=http://localhost:8080` | **HIGH** |

**Critical Note:** `.env.production` is tracked in Git and contains a plaintext HTTP URL. The `.gitignore` explicitly excludes `.env` and `.env.development` but does NOT exclude `.env.production`. The comment in `.gitignore` says `# Only .env.production remains tracked as it contains no credentials` — this justification is wrong; it contains the production API URL and establishes a dangerous precedent of tracking production config files.

## Vite Configuration

**File:** `vite.config.ts`

```typescript
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080/',
        changeOrigin: true,
        secure: false,      // ❌ Disables TLS verification (HIGH-009)
      },
    },
  },
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: './src/setupTests.ts',
  },
} as any)  // ❌ 'as any' cast bypasses TypeScript config type safety
```

**Security Notes:**
- `secure: false` should only be used when the backend has a self-signed certificate. Document this explicitly.
- The `as any` cast on `defineConfig` removes TypeScript type checking from the Vite configuration. This could hide misconfiguration silently.
- No `build.sourcemap` is set — source maps will be generated by default, potentially exposing source code in production. Add `build: { sourcemap: false }` for production.

### Source Map Risk

Without explicitly disabling source maps, Vite generates `.js.map` files in the `dist/` folder. If deployed to production, these allow attackers to reconstruct the original TypeScript source code from browser DevTools. **Fix:**

```typescript
// vite.config.ts
export default defineConfig({
  build: {
    sourcemap: false, // Disable in production
  },
  // ...
})
```

Or use different configs per environment:

```typescript
import { defineConfig, loadEnv } from 'vite';
export default defineConfig(({ mode }) => ({
  build: {
    sourcemap: mode === 'development',
  },
}));
```

## index.html Security Headers

| Header | Present | Value | Assessment |
|--------|---------|-------|------------|
| X-Content-Type-Options | ✅ | `nosniff` | Good |
| Referrer-Policy | ✅ | `strict-origin-when-cross-origin` | Good |
| Content-Security-Policy | ✅ (meta tag) | `unsafe-inline`, `unsafe-eval` | **Critical flaw** |
| X-Frame-Options | ❌ | Not set | Clickjacking risk |
| Permissions-Policy | ❌ | Not set | Missing |
| Strict-Transport-Security | ❌ | Not set (must be HTTP header) | Missing |

**Note:** `X-Frame-Options` and `Strict-Transport-Security` cannot be set via HTML meta tags — they must be HTTP response headers from the server/CDN.
